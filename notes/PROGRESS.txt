LOCAL / RENTED-GPU COMPARISON
Develop and validate the operator locally first. A single rented H100
is a useful second target, but is not required by these first steps.
Keep code snapshot, Python/Torch/Triton versions, dtype, tensor shapes,
causal flag, timing protocol and precision settings the same.
On each GPU compare naive attention, torch.compile, SDPA and the custom
kernel; record the selected SDPA backend. Calculate speedups within each
GPU before making cross-GPU comparisons. A different GPU's lower latency
alone is not evidence of a better implementation.
Record forward/backward latency, distributions, errors and peak memory;
separate cold compilation from warmed timings and record driver versions.
Laptop power/thermal state can influence results; save GPU telemetry
alongside serious benchmark runs. The first timings are an initial
baseline, not a controlled cross-hardware performance claim.
Use at least two GPUs for the later DDP/FSDP measurements, with the
interconnect topology and fixed-global-batch versus scaling-batch
settings documented.

CLOUD REPRODUCTION
The pip freeze editable Git URLs reference the upstream commit and omit local changes.
Use the supplied source snapshot instead, with:
conda env create -n CS336 -f environments/conda/environment.yml
conda activate CS336
pip install uv
uv pip install --python "$(command -v python)" --torch-backend=cu128 -r environments/conda/requirements-linux-pinned.txt -e . -e ./cs336-basics
bash scripts/run_first_baseline.sh
The pinned requirements include all installed non-editable pip packages; the editable source is supplied separately.
